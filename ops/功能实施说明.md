## 三、四个功能

### A. 任务 / 记事

| | 任务（task） | 记事（note） |
| --- | --- | --- |
| 需要确认完成 | 要 | 不需要，创建即完成 |
| 日期 / 重复 / 催办 / 优先级 | 可设 | 一律忽略 |
| 通知 | 按配置 | 永不通知 |
| 出现在哪 | 今天 / 计划 / 全部 / 已完成 | 只出现在**已完成** |

记事创建时直接写 `completed_at`。这一步同时白送了「不通知」——`rebuildJobs` 开头就是
`if reminder.CompletedAt != nil { return nil }`，记事根本不会生成投递任务。
任务与记事可在编辑器互相切换；`complete` 对记事是空操作，`restore` 明确报错。

### B. 已完成 + 时间段

**改动前「已完成」只显示 2 条，实际有 16 条。** 原因：你 34 条提醒里 24 条是重复提醒，
而重复提醒完成时**不写** `completed_at`，它往 `completions` 历史表插一条、把 `due_at` 滚到下一次。
上游代码里 `completions` 表**只写不读**，功能 B 是它的第一个读者。

```
改动前  已完成页可见            2 条
改动后  已完成页（全部时间段）  16 条   = 14 条历史 + 2 条完成记录
```

- 接口 `GET /api/reminder/completed?range=all|today|week|month|year|custom&from=&to=`
  数据源是 `completions` 历史 ∪ `reminders.completed_at`，按完成时间倒序
- 时间段按上海时区换算，**一周从周一算起**，自定义含结束日期当天
- 侧栏「已完成」角标改成同口径。历史计数作为子查询并进 summary 原有的聚合语句，
  保持 `/summary` 仍然只有 2 条查询（上游 `performance_test` 对此有硬约束）

### C. 默认清单设定

改动前 `is_default` 字段在、也参与排序与删除保护，但**没有任何接口能改它**。
现在 `PATCH /api/reminder/lists/:id` 支持 `is_default`，事务内保证任何时刻恰好一个默认清单；
拒绝 `is_default: false`（默认清单必须恒有）。前端在「偏好设置」加了选择器，侧栏默认清单带金色星标。

### D. 全屏日历

- 顶栏主题按钮旁新增 **列表 / 日历** 分段切换（只在提醒相关页面显示）
- 全屏月历：格子内是公历日 + 农历日名，**节日标红、节气标绿**；
  每天铺清单同色提醒条（最多 3 条，其余折成 +N；手机端只显示圆点）
- 右侧（桌面）/ 下方（手机）是选中日详情，可直接勾选完成；点标题跳到完整编辑器
- 数据来自新接口 `GET /api/reminder/calendar?from=&to=`，**含已完成项**（置灰划掉），
  区间左闭右开、跨度上限 70 天
- `due_date` 由后端按上海时区算好，前端按字符串归格 —— 不走浏览器时区换算，
  否则用户在非 +08 时区打开会整体错一天
- 农历网格直接复用已有的 `/api/reminder/lunar`：它本来就返回**周一起始、整周对齐**的
  完整网格（含相邻月份格子与节气节日），所以日历不用自己算网格

## 五、构建

上游 `Dockerfile` 在本机**跑不通**，全是网络问题，与业务代码无关：

| 问题 | 现象 | 处理 |
| --- | --- | --- |
| `alpine:3.20` 拿不到 | `registry-1.docker.io` 直连 EOF，加速器返回 401 | 改用本地 `alpine:latest`（3.24.2，与 `golang:1.26-alpine` 同版本，musl ABI 匹配） |
| apk 装不了 gcc | `dl-cdn.alpinelinux.org` 不可达且不稳定 | apk 走 `mirrors.aliyun.com`（并已预建 `reminder-builder:go1.26` 免去每次重装） |
| `npm ci` 失败 | 走代理仍 `ECONNRESET` | npm 走 `registry.npmmirror.com` |
| `go mod` 拉不到 | `proxy.golang.org` 不可达 | `GOPROXY=https://goproxy.cn,direct` |
| 运行阶段缺 tzdata | apk 装不上 | 从本地 `python:3.12-alpine` COPY `/usr/share/zoneinfo` |

> tzdata 不是可选项：`server` 多处 `time.LoadLocation("Asia/Shanghai")`，缺了它返回 `nil`，
> 紧接着的 `now.In(loc)` 会 **panic**。

**重建镜像：**

```bash
cd /vol1/@apphome/fn-deepseek-harness/编程开发/reminders-upstream
docker build -f Dockerfile.custom \
  --build-arg VERSION=v0.3.0-local \
  --build-arg BUILD_TIME=$(date +%Y-%m-%dT%H:%M:%S) \
  --build-arg GIT_COMMIT=$(git rev-parse --short HEAD) \
  -t reminders-local:v0.3.0-local .
```

**跑测试：**

```bash
docker run --rm -v "$PWD/server":/src -v go-mod-cache:/go/pkg/mod -w /src \
  reminder-builder:go1.26 sh -c 'CGO_ENABLED=1 go test ./...'
```

**重新部署到生产：**


## 六、已知限制

1. **删除非重复提醒后，它的完成记录会消失。** `completions` 历史表只在「重复提醒完成」时写入；
   非重复提醒的完成只体现在 `reminders.completed_at`，行被软删除后没有别的地方记录。
   重复提醒不受影响（靠 `title_snapshot` 保留）。
2. **已完成页的历史行是只读的**：底层提醒已删除时显示「提醒已删除」，不提供编辑/删除。
3. **日历不显示记事**（记事没有到期日），也不显示已完成提醒的**历史多次**完成记录——
   日历反映的是「提醒当前的到期时间」，重复提醒只落在下一次到期那天。
