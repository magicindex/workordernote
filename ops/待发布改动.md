### 0.25.0 已发布（2026-10-13 22:2x，三台）：「开始提醒时间」下新增「提前几天开始提醒」

用户原话：「开始提醒时间：reminder_all_day_time，增加 提前几天开始提醒，低于几天的按照正常流程走，
超过提醒天数的等符合设定时间后再开始执行提醒」。

- 新个人偏好 **`reminder_advance_days`**（TypeInt，默认 0 = 不提前，范围 0–60），
  与「开始提醒时间」同一张「提醒」卡片。
- 口径（`firstRemindAt` / `normalFirstRemindAt`）：
  · 离到期日**超过** N 天 → 首次提醒 = **(到期日 − N 天) 那天的「开始提醒时间」**；
  · 创建时就已经在 N 天之内（今天/明天到期）→ **按正常流程**（到期日当天那个「开始提醒时间」），一点不变；
  · 「开始提醒时间 = 00:00」时提前窗口照样生效（窗口落在 (到期日−N) 的 0 点）—— 00:00 的含义是
    「到期日当天不提前」，与「提前 N 天」是两件事。
- 窗口内**每天只在「开始提醒时间」提醒一次**（`scheduleRepeatNotify` 的窗口分支）：提前几天是让人
  心里有数，不是从三天前就按「提醒频率」每 15 分钟弹一次（那会变成几百条）；到了到期日那天
  恢复「首次提醒 + 提醒频率」的老口径。
- **新增配置写入钩子**（`sysconfig.RegisterChangeHook`）：改完「开始提醒时间 / 提前天数」立刻
  让 30 秒进程内缓存失效。原来改完设置 30 秒内的新建提醒会按旧口径排进投递队列、而且排完就定了
  （要再编辑一次才重排）—— 这是老毛病，这次一起修掉。
- 用例：Go 新增 `TestFirstRemindAdvanceDays` / `TestAdvanceWindowRepeatsOncePerDay` /
  `TestAdvanceDaysWorksWithMidnightStart` + `TestConfigChangeHookFires`；
  `verify-119` 扩到 **21 项**（设置页那一行是数字输入且在「提醒」卡片里、用管理员投递台账
  `/api/reminder/admin/deliveries` 断言「提前 3 天」与「正常流程」两种排期、改回 0 立刻生效）。
